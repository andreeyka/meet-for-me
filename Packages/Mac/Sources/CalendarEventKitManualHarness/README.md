# CalendarEventKitManualHarness

Носитель ручных критериев М1/М2 — перечень [MEE-339](https://linear.app/easypto/issue/MEE-339),
раздел «З», план проверки [MEE-343](https://linear.app/easypto/issue/MEE-343), §5. Каталог
принадлежит владельцу модуля `calendar-eventkit` (DEV-1) — правит только он.

Носитель вызывает `EKEventStore` НАПРЯМУЮ, в обход `calendar-eventkit` целиком — М1/М2 измеряют
факты о самом EventKit (граница «весь день», развёртка повторений, код ошибки при отозванном
праве), не поведение модуля (план §5: «оба пункта не тестируют код `calendar-eventkit`»).

Bundle id харнесса: **`com.andreeyka.meetforme.spike.calendar-eventkit.harness`** — отдельный и
от основного приложения, и от `CaptureManualHarness`/`spikes/capture-cli`. Право TCC
(Системные настройки → Конфиденциальность и безопасность → Календари) выдаётся именно на этот
bundle id.

## Сборка

```sh
Packages/Mac/Sources/CalendarEventKitManualHarness/scripts/build.sh
```

Собирает `CalendarEventKitManualHarness` (`swift build -c release --product
CalendarEventKitManualHarness`), оборачивает в `.build/CalendarEventKitManualHarness.app` и
подписывает сертификатом Apple Development (`IDENTITY=... scripts/build.sh` — переопределить
при другом сертификате). Пересборка тем же сертификатом сохраняет уже выданные права TCC;
ad-hoc подпись — нет.

`swift build`/`swift test` печатают предупреждение "unhandled files" на `Bundle/` и `scripts/` —
тот же принятый приём и то же ограничение, что у `CaptureManualHarness` (`Package.swift` вне
зоны этой задачи, владелец — архитектор; предупреждение не мешает ни сборке, ни CI).

## М1 — граница «весь день» и развёртка повторений (~15–20 мин)

1. В системном приложении «Календарь» создать тестовый календарь, в нём:
   * (а) событие «весь день», один день, без повторения;
   * (б) повторяющееся событие с ежедневным правилом, стоящее так, чтобы окно запроса
     захватывало **ровно три** вхождения (например, старт за день до окна, правило «каждый
     день», окно — 3 суток).
2. `tccutil reset Calendar com.andreeyka.meetforme.spike.calendar-eventkit.harness`
3. Запустить харнесс (через `open`, чтобы TCC отнёс промпт к bundle id харнесса, а не к
   терминалу); окно по умолчанию — 7 суток назад / 14 вперёд от текущего момента, сузить при
   необходимости `--days-back`/`--days-forward` под даты шага 1, `--calendar` — заголовком
   тестового календаря из шага 1, если в системе есть другие события в этом окне:

   ```sh
   Packages/Mac/Sources/CalendarEventKitManualHarness/scripts/run.sh \
     m1 --calendar "<заголовок тестового календаря>" --days-back 3 --days-forward 7
   ```

4. Дождаться системного промпта о доступе к Календарям; нажать **«Разрешить»**.
5. Харнесс печатает по каждому найденному событию одну строку (`title`, `isAllDay`, `start`,
   `end`, `eventIdentifier`, `occurrenceDate`, `hasRecurrenceRules`, вычисленный `externalId` —
   та же форма, что `EventKitCoreGateway.externalId(for:)`, `Sources/CalendarEventKit`), и
   сводку по заголовку внизу.
6. Заполнить дословно из вывода:

   | Что записать | Ожидание перечня/плана | Факт EventKit | Версия macOS |
   | --- | --- | --- | --- |
   | `end` события (а), «весь день» | `23:59:59` (или ближайшее представимое значение) последних суток события, НЕ первое мгновение следующих (C-001 «Поведение», К13 стоит на этом факте) | | |
   | Число `EKEvent` для события (б) | **три** отдельных значения, ни одно не свёрнуто в правило повторения (C-006 «Что вне контракта», К19 стоит на этом факте) | | |
   | `externalId` трёх вхождений (б) | все три различны (форма `EventKitCoreGateway.externalId(for:)`, `// СТРОКА:` там же — форма не названа контрактом, это решение DEV-1, М1 калибрует его стабильность, не сам факт) | | |
   | `eventIdentifier` трёх вхождений (б) | одно и то же значение у всех трёх (подтверждает довод возврата РП Д1, MEE-349: одного `eventIdentifier` недостаточно для уникальности `externalId`) | | |

   Расхождение любой строки — находка контракту/перечню (владелец — аналитик), не чинится этим
   прогоном.

## М2 — калибровка различения «похоже на потерю права» (Р7) (~10–15 мин)

1. `tccutil reset Calendar com.andreeyka.meetforme.spike.calendar-eventkit.harness`
2. Запустить харнесс с запасом времени на шаг 3 (по умолчанию 20 секунд паузы,
   `--wait-seconds` — увеличить при необходимости):

   ```sh
   Packages/Mac/Sources/CalendarEventKitManualHarness/scripts/run.sh m2 --wait-seconds 20
   ```

3. Дождаться системного промпта; нажать **«Разрешить»**. Харнесс печатает статус права и
   начинает отсчёт паузы.
4. **В течение паузы** отозвать право: Системные настройки → Конфиденциальность и
   безопасность → Календари → снять галочку у `CalendarEventKitManualHarness`. Если системный
   UI не успевает среагировать в отведённое окно — ближайший воспроизводимый аналог,
   выполненный в течение той же паузы, в отдельном терминале:

   ```sh
   tccutil reset Calendar com.andreeyka.meetforme.spike.calendar-eventkit.harness
   ```

5. После паузы харнесс вызывает `calendars(for: .event)`, затем `events(matching:)`, и печатает
   исход каждого вызова. **Оба метода в документированном API EventKit — не `throws`**
   (см. `// СТРОКА:` у развилки Р7 в `Sources/CalendarEventKit/EventKitCoreGateway.swift`) —
   возможных исходов три, не один:
   * оба вызова доходят до печати "дошли без исключения" с непустым/пустым числом — право
     не помешало вызову синтаксически;
   * процесс завершается необработанным исключением ДО следующей ожидаемой строки — тогда
     исход смотреть в `Packages/Mac/.build/logs/<время>.err` (класс/`reason` NSException);
   * (наблюдалось на прежних версиях EventKit) вызов проходит, но результат пуст там, где до
     отзыва он не был бы — сравнить число календарей/событий с прогоном без отзыва.
6. Повторить пп. 1–5 **вторым, независимым способом отзыва**, если первый недостаточно чётко
   воспроизводится (например, `tccutil reset` вместо снятия галочки в UI, или наоборот) — план
   требует калибровки, не одного удачного повторения.
7. Заполнить дословно:

   | Что записать | Значение |
   | --- | --- |
   | Способ отзыва (UI / `tccutil reset`) | |
   | Какой вызов первым отразил утрату права (`calendars(for:)` / `events(matching:)` / ни один) | |
   | Тип/класс ошибки (NSError domain/code, `EKError` case, либо класс NSException из `.err`) | |
   | Полный текст `localizedDescription` / `reason` исключения | |
   | `errorCode`, если доступен | |
   | Версия macOS | |
   | Второй способ отзыва дал тот же результат? | |

   Итог — единственный источник, калибрующий развилку Р7 (различение «похоже на потерю
   права» / «иная причина», `Sources/CalendarEventKit/EventKitCoreGateway.swift`); без него
   классификация в шве остаётся эвристикой без проверенного основания (перечень MEE-339, М2).
